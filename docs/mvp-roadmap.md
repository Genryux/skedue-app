# MVP Roadmap

## Delivery Strategy

Skedue should be built in phases so the product becomes usable early while leaving space for refinement.

## Phase 0: Foundation

Outcome:
Shared product understanding before implementation.

Deliverables:
- product vision,
- PRD,
- information architecture,
- MVP scope definition,
- design direction alignment.

## Phase 1: Core academic structure

Outcome:
Students can set up the backbone of their semester.

Scope:
- authentication if needed for saved user data,
- subject CRUD,
- recurring schedule data model,
- today and this week schedule filters,
- subject list view,
- subject detail shell.

Success signal:
A student can create subjects and trust the app to reflect their weekly class schedule.

## Phase 2: Subject productivity workspace

Outcome:
Students can start using Skedue daily for class work.

Scope:
- subject tasks,
- subject notes,
- folders with color customization,
- uncategorized notes area,
- note pinning,
- basic rich-text formatting.

Success signal:
A student can manage notes and tasks without leaving the subject workspace.

## Phase 3: Timetable and sharing

Outcome:
Students get stronger planning and collaboration value.

Scope:
- timetable view,
- individual note sharing,
- note search inside folders or subjects.

Success signal:
Students can visually scan their week and send useful notes to classmates.

## Phase 4: Quality and expansion

Outcome:
Polish, reliability, and retention improvements.

Possible scope:
- better reminders,
- offline drafts,
- upcoming tasks dashboard,
- attachments,
- analytics on usage,
- collaboration upgrades.

## Recommended MVP Cut Line

If we need to keep the first release lean, the strongest MVP cut line is:
- subjects with recurring schedules,
- today and this week views,
- subject detail page,
- tasks,
- notes,
- folders with color,
- and a simple timetable.

Move note sharing to post-MVP if engineering or security complexity becomes too high.

## Suggested Next Decisions Before Coding

1. Confirm the exact MVP cut line.
2. Decide whether Skedue is mobile-only first or mobile plus web.
3. Decide whether note sharing is public link, invite-only, or post-MVP.
4. Choose the note editor approach.
5. Define the initial visual system from your mockups.
